# Database Migrations with Alembic

This guide explains how to manage database schema changes using Alembic in the FastAPI_Auth project.

## What is a migration?

A migration is a versioned script that changes the database schema. Instead of manually running SQL commands, you let Alembic generate and track these changes. This ensures:

- Your database schema matches your code models
- Changes can be rolled back if something breaks
- Team members can apply the same schema changes consistently

## Prerequisites

Alembic is already installed and initialized in `backend/`. The configuration files are:
- `backend/alembic.ini` — Alembic settings
- `backend/alembic/env.py` — Migration environment (imports your models)
- `backend/alembic/versions/` — Where migration scripts are stored

## How Alembic Works

1. You define your database structure using SQLAlchemy models in `db_models.py`
2. Alembic compares your models against the actual database
3. Alembic generates a migration script with `upgrade()` and `downgrade()` functions
4. You run `alembic upgrade head` to apply the changes

## Common Commands

Run all commands from the `backend/` directory.

### Generate a new migration

```bash
alembic revision --autogenerate -m "Add phone column to users"
```

This inspects your models, compares them to the database, and creates a new migration file in `backend/alembic/versions/`.

### Apply migrations

```bash
alembic upgrade head
```

Applies all pending migrations to bring the database to the latest version.

### Roll back a migration

```bash
# Roll back one migration
alembic downgrade -1

# Roll back to a specific version
alembic downgrade abc123
```

### Check current status

```bash
# Show current database version
alembic current

# Show migration history
alembic history
```

## Workflow Example

Suppose you want to add a `phone` column to the `User` table.

### Step 1: Edit the model

```python
# backend/app/db_models.py
class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True, index=True)
    username = Column(String(100), unique=True, index=True)
    email = Column(String(100), unique=True, index=True)
    hashed_password = Column(String(100), nullable=False)
    phone = Column(String(20), nullable=True)  # NEW
```

### Step 2: Generate migration

```bash
cd backend
alembic revision --autogenerate -m "Add phone column to users"
```

### Step 3: Review the generated script

Open the new file in `backend/alembic/versions/` and check that it does what you expect.

### Step 4: Apply the migration

```bash
alembic upgrade head
```

## Important Notes

- **Always review autogenerated migrations.** Alembic may miss changes or make incorrect assumptions.
- **Never edit `alembic/versions/` files that have already been applied in production.**
- **The `alembic_version` table** in your database tracks which migrations have been applied.
- **Models and migrations must stay in sync.** If you change a model without generating a migration, your database will be out of date.
- **Run migrations before starting the app** if you have pending changes.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `Target database is not up to date` | Run `alembic upgrade head` |
| `Can't find revision` | Check that the migration file exists in `versions/` |
| `No changes detected` | Make sure you actually changed a model, and that `target_metadata` is set in `env.py` |
| `Import error` | Ensure `sys.path` in `env.py` points to your `backend/` directory |
